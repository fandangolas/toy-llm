## Q / K / V — Query, Key, Value

### The problem

After tokenization, the model has a sequence of vectors — one per character. But each vector only knows about itself. The word "it" doesn't know what it refers to. The word "not" doesn't know what it's negating. Tokens need a way to look at each other and gather relevant information.

Q/K/V is the mechanism that makes this possible.

---

### The intuition

Think of a library search:

- You walk in with a **query** ("books about Roman history")
- Every book has a **key** on its spine (title, subject tags)
- Your query is matched against all keys to find the most relevant ones
- You take the **value** (the actual content) from the best matches

In attention, every token simultaneously plays all three roles:
- It has a **Query** — "what information am I looking for from the rest of the sequence?"
- It has a **Key** — "what information do I contain that others might want?"
- It has a **Value** — "what will I actually share if someone attends to me?"

---

### How it works, step by step

Take a sequence: `"the cat sat"`

**Step 1 — Produce Q, K, V for every token**

Each token's embedding vector (128 numbers) is multiplied by a learned weight matrix to produce three new vectors: its Q, its K, and its V. This is one linear projection that outputs all three at once:

```python
# attention.py line 16
self.qkv_proj = nn.Linear(n_embd, 3 * n_embd, bias=False)

# attention.py line 29
q, k, v = self.qkv_proj(x).split(self.n_embd, dim=2)
```

`nn.Linear(128, 384)` holds a weight matrix of shape `(128, 384)`. When you pass `x` through it, you get a `(384,)` vector per token, which is then split into three `(128,)` vectors: Q, K, V.

These weights are what the model learns during training. Initially random, they gradually become good at producing Q/K/V vectors that are useful for predicting the next token.

**Step 2 — Score every token against every other token**

For each token, compute the dot product of its Q against every other token's K:

```
score(i, j) = Q[i] · K[j]
```

This produces a matrix of scores of shape `(T, T)` — T tokens × T tokens. Entry `[i, j]` answers: *how relevant is token j to token i?*

For `"the cat sat"`, token `"sat"` might produce a high score against `"cat"` (the subject) and a low score against `"the"` (less relevant for predicting what comes after `"sat"`).

**Step 3 — Normalize scores into weights**

Apply softmax to each row so the scores become probabilities that sum to 1:

```
weights[i] = softmax(scores[i])   # how much token i attends to each other token
```

**Step 4 — Collect information**

Each token's output is a weighted average of all V vectors:

```
output[i] = sum(weights[i, j] * V[j]  for all j)
```

Token `"sat"` ends up with an output that blends information from all tokens, but weighted toward the ones it scored highest — likely `"cat"`.

---

### Why three separate vectors?

You might ask: why not just use the token's own embedding directly for scoring?

Because Q, K, and V are different *projections* of the same token, each optimized for a different purpose:
- **Q and K** need to be good at *matching* — their dot products should reflect semantic relevance
- **V** needs to be good at *carrying information* — it's what actually flows when attention is paid

Keeping them separate lets the model learn these roles independently. The weight matrix `qkv_proj` is what encodes this separation.

---

### PyTorch's role here

| What we need | How PyTorch provides it |
|---|---|
| The Q/K/V weight matrices | `nn.Linear(n_embd, 3 * n_embd)` — allocates and initializes the matrix, registers it as a learnable parameter |
| Applying the projection | Calling `self.qkv_proj(x)` runs the matrix multiply `x @ W^T` |
| Splitting Q, K, V | `.split(n_embd, dim=2)` — slices the output into three equal chunks |
| Learning the weights | Autograd — every operation on an `nn.Linear` output is recorded, so `loss.backward()` automatically computes how to adjust these weights to reduce loss |

The key point: you never write the update rule for these weights. You define the forward computation, PyTorch records it, and `optimizer.step()` adjusts every weight in the direction that reduces loss.
